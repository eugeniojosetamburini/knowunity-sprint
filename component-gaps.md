# Component gaps

Things a screen needed that weren't in Storybook at the time (see
`.claude/skills/build-screen`, step 5). A gap hit by a second screen gets
promoted to a real component; the line stays, marked built, as history.

- Screen shell (`.screen` / `.frame`, 390px, page background) — hand-rolled on Home, Due list, and Recap; drifted between them (different bar heights, bottom nav position, scrollbar shift). **Built as `Scaffold`** (`stories/components/Scaffold`), all three routes migrated.
- Home-level top bar (hamburger / PRO / streak / fire / recall badge / alarm) — inlined on Home, then again on Due list. **Built as `TopNav`** (`stories/components/TopNav`), both screens migrated. Not an `appBar` variant, per design-system.md's own note.
- Flow-screen top bar (back arrow / progress / more) — design-system.md's `appBar` (one left icon, up to two right elements), not in Storybook. Inlined on Entry/recap, the prompt screen, Processing and Result: Pass — four copies of the same markup and CSS. **Built as `AppBar`** (`stories/components/AppBar`, with stories), all four routes migrated; `BackButton.tsx` and the screen-local `icons.tsx` were absorbed into it and deleted. Purpose-built like `TopNav` rather than a generic slot container, with `progress` optional for a screen that has the bar but no session progress (e.g. Summary, SPEC.md #10).
- "Greed Narrow-TRIAL" headline style (Home's referral headline, 28px/34px) — no font file and no token anywhere in the project. **Open.** Home falls back to `typography.headline.m`; flagged in `app/page.module.css`.
- Scaffold slot 5, bottom sheet + scrim — needed by the Exit-session confirm dialog (SPEC.md #15). **Open**, nothing built. Not to be confused with slot 4's new flush form (below): slot 5 is the *modal, scrimmed* sheet, this one is a persistent footer.
- Flow-screen action sheet (rounded-top surface, drag handle, Retry + Continue row) — the footer on every result screen (SPEC.md #7/#8/#11). The positioning went into `Scaffold` as slot 4's flush form (`bottomNavFlush`), since pinning to the viewport bottom is shell behavior. **Built as `ActionSheet`** (`stories/components/ActionSheet`, with stories) when Incorrect and Partial needed the identical sheet; the Pass screen was migrated onto it. Flagged: `actionSheet` is not a component design-system.md names — worth adding there, or folding into slot 5's definition.
- "Choose your own topics" destination (Due list) — the link is a real tap target but no topic-picker screen exists. **Open**, not a component gap so much as a missing screen.
- Flow-screen bar with a **title** instead of progress — needed by the Summary (SPEC.md #10), whose frame centres "Summary" where every other flow frame centres the progress bar. Not a new component: `AppBar` already existed and already had `progress` documented as optional for exactly this screen, so it gained an optional `title` sharing that centre slot (plus a story). Purely additive — no existing screen passes it, so nothing else changed. **Flagged:** Figma sets the title in Greed Standard *Medium* (500) and `tokens/tokens.json` has no 500 weight at all (regular / 600 / bold only), so it renders one rung heavy at `typography.body.s.bold`. Wants a token, or a frame change.
- "Change review time" destination (Summary) — a real tap target with no reschedule screen behind it, and none in scope. **Open**, the same shape of gap as the due list's "Choose your own topics" (and, like it, not really a component gap but a missing screen).
- Due list, all-caught-up state (SPEC.md #2a) — no frame, no component missing either: built from the existing `TopNav` / `BottomNav` / `MascotSlot` with the card list swapped for one line of copy. Recorded here only because `TopNav` has no way to *hide* the recall badge, so "nothing due" is expressed as a `dueCount` of "0" rather than an absent badge. **Open** if a real empty state ever wants the badge gone.
- `textBlock` — needed by the text fallback (SPEC.md #14). **Built** (`stories/components/TextBlock`), but not as anything expected: the Figma component (node 9003:9039) turned out to be a read-only title/caption display pair, not the input its own description, `docs/design-system.md` and `CLAUDE.md` all claimed. Built as drawn, and the input those docs were describing was built alongside it as `TextField`. Both docs corrected; the **Figma component's name and description still want fixing at source**.
- Free-text input for the student's own answer — **Built** as `textField` (`stories/components/TextField`, with stories). **No Figma component or frame exists for it**, so every value is composed from tokens whose descriptions specify the use rather than measured off artwork. Wants checking against a real frame if one is ever drawn. Unblocks SPEC.md #14.
- `buttonGroup` — named in `docs/design-system.md` and `CLAUDE.md` but never built. **Built** (`stories/components/ButtonGroup`, with stories) when the exit-session confirm needed a sheet's action slot, which Figma's own description names as its confirmed use. Composed from the real `Button`/`ButtonIcon`. Flagged: its `horizontal` variant is an icon button plus a primary, not two labelled buttons, and its size-M secondary fill disagrees with the standalone `button` component at source.
- Scaffold slot 5, bottom sheet + scrim — **Built** as `bottomSheet` (`stories/components/BottomSheet`, with stories), closing the gap opened when the exit-session confirm was first scoped. No Figma frame, so the composition is interpreted from `docs/design-system.md`'s slot-5 description; the surface reuses `actionSheet`'s measured geometry so the two sheets match. Two interpretations flagged there: it renders nothing while closed rather than "collapsed to a sliver", and it is fixed to the viewport rather than a fifth `Scaffold` prop. Unblocks SPEC.md #15 (which still needs #16, the ⋯ menu, to be reachable).
- Text-fallback trigger zone (field + Submit + "Use voice instead") — needed by the prompt screen and the hint screen (SPEC.md #14). Built as `app/recap/[topicId]/TypeTrigger.tsx`, **screen-local rather than a Storybook component**, following the precedent its sibling `MicTrigger` already set for the voice zone the two screens share: this is screen composition, and no Figma frame or component covers it. Uses the real `TextField` and `Button` inside. If a third screen ever needs it, promote it.
- Student's own utterance, echoed back — needed by the result screens when a term was answered by typing (SPEC.md #14). **Built inline** in `app/recap/[topicId]/result/[termIndex]/page.module.css` (`.typedAnswer`). No component covers it: `ChatBubble` is explicitly Knowie's dialogue only (design-system.md), and `TextBlock` is a title/caption pair. **Open** — if a second screen ever shows the student's own words back, this becomes a real component.
- ⋯ menu (SPEC.md #16) — needed by the four mid-session screens. **Built into `AppBar`** as an optional `menuItems` prop (with a story) rather than as a separate component or four screen-local copies: `AppBar` owns the ⋯ button, and four copies of a popover would drift the way the bar itself once did. No Figma frame or component covers a menu; its surface is `background.floating`, whose own token description names dropdowns and popovers as its use. **Flagged:** no destructive *text* token exists, so the destructive item is tinted with `interactive.destructive`, which is defined as a fill.
- Exit-session confirm (SPEC.md #15) — **built** as `app/recap/[topicId]/ExitSession.tsx`, screen-local and shared by the four mid-session screens, following `MicTrigger` / `TypeTrigger`. It composes the real `BottomSheet` + `TextBlock` + `ButtonGroup`, so no new surface was invented. Closes the slot-5 gap opened when this screen was first scoped. **`ButtonGroup` gained `tone="destructive"`** for it — additive, nothing else used it; the Figma set wants the variant adding at source.
